# مُلازَمَة — إطلاق الصفحة التعريفية المحدود

## نطاق التسليم
- ملف واحد ثابت: `launch/limited/index.html`، مستقل عن Vite وReact وFSRS وبيانات المتعلم والمصحف.
- لغة عربية واتجاه RTL، متجاوب دون JavaScript أو مكتبات أو تحليلات أو خطوط خارجية أو نماذج أو ملفات تعريف ارتباط ينشئها التطبيق.
- لا يحتوي نصًا قرآنيًا أو قارئًا أو وظائف الحفظ أو المراجعة أو التسميع.
- لا يوجد رابط إلى وضع الاختبار الصناعي أو المعاينة الخاصة، ولا ادعاء بإتاحة التطبيق أو اعتماده.

## حدود الاعتماد
- هذه **مسودة للمراجعة** وليست موافقة على النشر. يجب أن تعتمد المالكة النص والهوية والحقوق قبل رفعها.
- `productionReady=false` وG01–G10 تخص التطبيق القرآني ولا تتغير بهذه الصفحة. لا يجوز تعديلها أو الالتفاف على مسار إصدار التطبيق.
- النشر التعريفي المحدود مستقل من حيث المحتوى، لكن لا ينفذ إلا بإذن منفصل صريح بعد التحقق من SSL/HTTPS وصحة إعداد النطاق والمسار والنسخ الاحتياطي.
- لا تستخدم `.github/workflows/deploy-ftps.yml` الحالي للصفحة؛ فهو معد لتوزيعة `dist/` المعتمدة، ويتطلب بوابات الإصدار.

## متطلبات الاستضافة قبل أي نشر
1. إثبات توجيه `mulazama.com` إلى الاستضافة الصحيحة وعمل شهادة HTTPS صالحة للنطاق؛ والتحقق من `www` أيضًا إذا كان مستخدمًا.
2. الحصول من مزود الاستضافة على **اسم مضيف FTPS تطابقه شهادة TLS**، ثم إعادة الفحص للقراءة فقط. آخر فحص في PR #13 فشل باسم مضيف غير مطابق للشهادة حتى بعد الوصول إلى AUTH TLS؛ لا تلغِ التحقق من TLS ولا تستخدم FTP غير المشفر.
3. التحقق من موقع جذر الويب (قيل إن الحساب يدخل مباشرة إلى `public_html`) دون التخمين أو رفع ملفات قبل التأكد؛ الاحتفاظ بنسخة احتياطية من `index.html` القديم إن وجد.
4. التحقق من استجابة `200` لصفحة البداية و`Content-Type: text/html; charset=UTF-8` ومن توجيه HTTP إلى HTTPS. تعطيل إدراج الموارد أو قوائم الملفات غير المقصودة.
5. إعداد رؤوس الحماية على الاستضافة بعد اختبارها. المقترح لهذه الصفحة الثابتة: `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`، مع `X-Content-Type-Options: nosniff` و`Referrer-Policy: no-referrer`. راجع سياسة استضافة CSS المضمّن قبل تفعيلها.
6. مراجعة ملاءمة إشعار الخصوصية للصفحة الثابتة وسجلات الخادم التي يديرها المضيف قبل النشر، ولا تنقل سياسة التطبيق غير المعتمدة إلى الصفحة التعريفية على أنها نهائية.

## اختبار قبل النشر
- افتح `launch/limited/index.html` محليًا في المتصفح أو على استضافة معاينة خاصة؛ تحقق من النص والعنوان والشاشات الضيقة، واللغة، والتنقل إلى قسم «عن المشروع».
- افحص المصدر للتأكد من عدم وجود `script` أو `form` أو اتصالات خارجية أو أصول قرآنية.
- اختبر استجابة HTTPS الفعلية وشهادة النطاق عند النشر.

## الرفع المقترح بعد الاعتماد فقط
بعد تجاوز نقاط الاتصال والاعتماد، ارفع **محتوى** ملف `launch/limited/index.html` بوصفه `index.html` في الجذر الصحيح للموقع، مع الاحتفاظ بنسخة من الملف السابق. لا ترفع جذر المستودع أو `dist/` أو `dist-engineering/` ولا تغيّر ملفات التطبيق. لا تفعّل نشرًا تلقائيًا أو تدمج فروع المصحف ضمن هذا الإجراء.

## التراجع
استعد `index.html` السابق من النسخة الاحتياطية بعد التحقق من عدم تغيّر محتواه، ولا تمس سجلات المتعلمين أو ملفات الاستضافة الأخرى.

## نتائج هذا العمل
- أنشئت الملفات في فرع مراجعة مستقل، **ولم تُرفع إلى الاستضافة**.
- لم تُغيّر صلاحيات أو أسرار أو إعداد DNS أو ملفات التطبيق أو بوابات الإصدار.
- اختبارات المتصفح وTLS والخادم الحي لم تُنفَّذ من هذه المهمة؛ لا يُدّعى نجاحها.
