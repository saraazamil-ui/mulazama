## ما تغير

ثبت أن الحالات30 الأصلية تختلف بسبب التقريب المرحلي فيts-fsrs5.4.2؛ كشفت الحواف أيضًا أثر ترتيب العمليات عند نصف الفاصل. لم تتغير المدخلات32 أو السماحية أو الأوزان أو سلم التقييم لإخفاء الفشل.

ReferenceFsrsAdapter ومسارrebuildAdaptiveSchedule يقدمان الحساب المصحح من الملاحظات الأصلية وآخر التصحيحات. تبدأ كل ذاكرة منnull وتبقى النتيجة هندسية منفصلة، بلا كتابة أو موعد تنفيذي. FsrsAdapter التاريخي وإصدارات الوقائع كما هي لحماية إعادة الفتح والخطط القديمة، ولا ندعي أنه أصبح مطابقًا.

projectPersonalMemory يبني ملف أدلة لكل وحدة وطبعة، دون توقعات إتقان أو ثبات أو تاريخ حفظ مفترض. قراءتاHistoryApplication الجديدتان لا تضيفان حدثًا أو جدولًا إلىIndexedDB. [خطة التغيير والترحيل](docs/06e1/Change-and-Migration-Plan.md) كُتبت قبل التنفيذ؛ [06-E2 المقترحة](docs/06e1/Next-Phase-06E2.md) تفصل الانتخاب والترحيل عن نجاح المقارنة.

## التشغيل والتحقق

Node24+ وpnpm11.25.0؛ التبعيات والقفل لم يتغيرا. ZIP لا يتضمنnode_modules ولا بيانات مستخدمين.

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
pnpm verify:build
pnpm dev
```

افتحlocalhost ثم `/#S05` أو `/#S14`. لا يبدأ الملف الجديد بنشاط صناعي. تصميم06-D2 وحجب النسب غير المعتمدة محفوظان؛ الذاكرة الجديدة أساس تقني ولا تعرض الواجهة احتمالات أو استحقاقات غير معتمدة.

```sh
PW_CHANNEL=chrome python3 scripts/verify-06e1.py --node /path/to/node --browser
node scripts/verify-fsrs-reference-06e1.mjs
node scripts/fsrs-06e1-investigation.mjs --probe-module src/conformance/fsrs-reference-probe.ts
```

يلزمChrome أوChromium مثبت وصلاحيةlocalhost. تحقق المرجع يستعمل تنزيلات رسمية محفوظة مع إيصال جلبها؛ لا يدعي جلبًا جديدًا على كل تشغيل. يختبر الأمر توقيعnpm محليًا، ولا يدعي تحققSigstore. أمر البوابات يستعمل05-C لأنها سياسة الاعتماد القائمة ويعيدexit2 للحجب؛ لا يتجاوزها المشغل.

بعض الاختبارات الموروثة تكتب قياسات فيتقارير05b و06d2. عند إعداد تسليم جديد، احفظ تلك المخرجات فيأدلة المرحلة الجديدة ثم استرجع التقارير التاريخية، كما فُعل هنا.
