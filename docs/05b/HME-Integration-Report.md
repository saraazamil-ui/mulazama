# HME Integration Report — MULAZAMA Phase 05-B

هذا تقرير تحقق لخدمة التعلم الفعلية في مُلازَمَة (MULAZAMA)، وليس اعتمادًا علميًا للحفظ أو إذنًا بفتح جلسات القرآن. جميع الأهداف والمفاتيح ونطاقات الاختبار في الاختبارات الجديدة صناعية، ولا تتضمن آيات أو نصًا شبيهًا بالقرآن. التخزين المستخدم هنا هو `MemoryEventStore` المعاملاتي؛ هذه النتائج لا تثبت IndexedDB أو تشغيل متصفح أو هاتف.

## المرجع وحدود المراجعة

قُرئت الشيفرة المسلمة في 05-A، وتقرير جاهزيتها، والمقاطع التشغيلية ذات الصلة من النسختين الحاليتين المحفوظتين في `references/HME-current-source.md` و`references/PRD-current-source.md`. شملت المراجعة HME §§6،9،13،15،16،18 وعقود PRD C03–C07 وقواعد الأحداث والقبول AC05/09/10/11/13/16/18/21/22/25. لم تُغير معادلات FSRS أو حدود سياسة P0 في هذه المراجعة.

كانت خدمة 05-A تختبر تكرارات وتلميحات واستئنافًا وتصحيحات تاريخية بوحدات صناعية، بينما بقيت واجهات التعلم الإنتاجية محجوبة. كشف التحقق الإضافي عيوبًا لم تغطها مجموعة الاختبارات السابقة؛ لا يُعد نجاحها السابق دليلًا على غياب تلك العيوب.

## نتائج التشغيل والأدلة

- `evidence/hme-regressions-before.json`: تشغيل قبل إصلاح المصدر؛ 10 حالات جديدة فاشلة، صفر نجاح. تبين هذه اللقطة أن الانحدارات قابلة للإعادة، وليست قائمة مقترحات.
- `evidence/hme-cluster-regression-before.json`: قبل إصلاح منع تكرار العنقود؛ HV08 يفشل فعليًا، ومعه HV05 الذي انتظر إصلاح refresh؛ 11 حالة ناجحة وحالتان فاشلتان.
- `evidence/hme-integration-initial.json`: مسودة تحقق للرحلات أظهرت 4 أخطاء في توصيل الاختبار نفسه (اسم حقل connectedStatus، اشتمال reasonCodes في PlanCandidate، وكلفة لا تتسع بعد الاحتياط). صُححت هذه الاختبارات الجديدة وفق واجهات النواة والمواعيد؛ لم تُغير معادلات أو قيم الاختبارات التاريخية لتغطية فشل مصدر.
- نتيجة التشغيل النهائية المسندة في `evidence/hme-application-final.json`: **110 ناجحة، صفر فشل، صفر تجاوز أو انتظار**. منها 16 حالة تعلم موروثة، و24 حالة تحقق أدلة جديدة، و5 رحلات تكامل جديدة، و65 حالة نواة HME موروثة. لا تُضاف الأعداد الوسيطة إلى هذا المجموع. نجح أيضًا فحص TypeScript بعد دمج واجهة التصريح.

الأمر: `node node_modules/vitest/vitest.mjs run src/application/learning.test.ts src/application/learning-validation.test.ts src/application/learning-validation.integration.test.ts src/core/hme.test.ts --reporter=json --outputFile=docs/05b/evidence/hme-application-final.json`، مع Node 24.22.1 وVitest 3.2.4 على macOS arm64. فحص TypeScript مستقل ضمن أدلة التسليم النهائية.

## الموانع والحدود الباقية

1. سلامة النص/الخط/التقطيع والاعتماد البشري والمطابقة المستقلة لـFSRS بوابات منفصلة. لا يمنح نجاح خدمة التعلم أيًا منها.
2. مخططات الوحدة تتحقق من البنية فقط؛ مطابقة words/coverage/edition/profile للبايتات والحدود المعتمدة مسؤولية حزمة المحتوى الموثوقة وطبقة تصريح الخدمة. لا يكفي فحص editionId أو الاسم.
3. المجدول يقبل V1 مع سقوفه البحثية، ولا يستطيع اكتشاف كل تقرير ذاتي مختلق. صلاحية gapVerified تظل محدودة بصدق التقرير وسلامة الساعة؛ لا توجد هنا مصادقة مستقلة على الساعة أو عداد رتيب موصول بالأجهزة. رفض رجوع الساعة ليس اعتمادًا شاملًا لساعة الجهاز.
4. لا توجد هجرة مُعتمدة لخام التعلم 05-A إلى معنى الأدلة الجديد. الرفض يحفظ الخام ويمنع إعادة تفسيره بصمت؛ يلزم shadow replay وتقرير فروق وموافقة سياسة قبل أي هجرة.
5. الخدمة لا تبني جميع المرشحين تلقائيًا من محتوى معتمد؛ تتحقق من مرشحي الأهداف والمواعيد وتمنع إسقاط الدين. costMinutes وfutureLoadFeasible يظلان مدخلين يحتاجان مصدر تقدير مُراجع قبل التفعيل.
6. استبدل اشتقاق طبقات RecoveryStarted من unknown للجميع إلى recent_weak/old_due/unknown بحسب الإخفاقات والاستحقاقات الفعلية في البادئة الزمنية. بقيت 3 دقائق افتراضية لكل وحدة؛ يظهر الآن `costModelVersion=recovery-fallback-3-minutes-05a` و`costModelValidated=false` مع بيان أن هذا ليس زمن مستخدم مقاسًا. لا تُعتمد كفاية زمن الاستعادة إنتاجيًا من هذا الافتراض.
7. دعم التسجيل/مصدر V2 والقياسات التفصيلية attemptedSpans/promptedSpans والتجويد غير مكتمل. الملاحظات nullable لا تصبح صفرًا، ومسودة خطأ لا تُختلق منها محاذاة لفظية.
8. التسميع المتصل والبدء العشوائي منفصلان. probeType المصحح لا يكفي لإنشاء خرائط روابط وتغطية أكبر تلقائيًا. التقييم المشاهد محفوظ لغير chunk، ولكن `schedulerStatus=profile-not-approved` يمنع تطبيق معاملات chunk عليه؛ ليست لديه حالة FSRS أو مواعيد نموذجية حتى اعتماد profile مناسب. غياب الدليل يبقى مجهولًا، ولا يمنح Maintenance.
9. نتائج هذه المجموعة لا تشمل IndexedDB، انقطاع طاقة فعلي، متصفحات، iOS أو Android أو قارئات شاشة. تُقرأ تقارير تلك المجموعات مستقلة ولا تجمع نتائجها هنا.

**الحكم لهذه الطبقة: منفذة جزئيًا مع تحقق صناعي فعلي، وبوابة جلسات القرآن الإنتاجية مستمرة في الحجب حتى اكتمال الاعتمادات المنفصلة.**
