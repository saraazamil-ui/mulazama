# MULAZAMA — FSRS Conformance Report

تاريخ التحقق: 5 نوفمبر 2026. **قرار G02: Blocked.** لم تثبت مطابقة مكتبة منشورة، ولم تُفتح الجدولة الإنتاجية. نجاح فحص الحساب البحثي أو اختبارات أداة المقارنة لا يغير هذا القرار.

## ما فُحص وما نُفذ

قُرئ التنفيذ الحقيقي `src/core/fsrs.ts` واختباراته وملف نتائجه المستقل، وتقرير 05-A الحسابي والجاهزية، وأقسام HME 12 و18 و19 وعقود PRD C07 وC11 وD13. لم يُعدَّل التنفيذ الحسابي السابق أو أوزانه أو توقعات اختباراته. لا تحمل إضافة 05-B نصًا قرآنيًا أو سجل مستخدم.

أُضيفت بنية اختبار تعمل فعليًا:

- `src/conformance/fsrs-suite.ts`: **23 حالة إدخال في 12 فئة**، مع الدرجات الأربع للتهيئة وللمراجعة في اليوم نفسه، وحالات زمن وحدود وإعادة تشغيل.
- `src/conformance/fsrs-conformance.ts`: مقارنة النتائج، سماحية عددية معلنة، فروق لكل حقل، رفض النسخ/الأوزان المختلفة، وفحص الحتمية وعدم تعديل المدخلات. القيم المتوقعة لا تُنشأ من تنفيذ مُلازَمَة.
- `scripts/fsrs-reference-loader.mjs`: يفحص SRI ‏SHA-512 مقابل بيانات npm المقدمة، وبنية tgz محدودة الحجم، وبصمة **كل ملف** في الاستخراج ومطابقته للأرشيف، والنسخة والالتزام والترخيص قبل الاستيراد. يرفض مسارات الخروج والروابط الرمزية والتكرار وأنواع أرشيف غير مدعومة والتبعيات غير المثبتة. التحقق من البصمات لا يثبت وحده منشأ بيانات npm؛ يلزم فحص منشئ الدليل واعتمادها في سياسة الإصدار.
- `scripts/fsrs-reference-prepare.mjs`: تجهيز محلي من ملف npm metadata وtgz معروفين، دون شبكة أو تشغيل package scripts أو تغيير الاعتماديات. يحافظ على البايتات ويرفض استبدال مجلد سابق.
- `scripts/fsrs-conformance.mjs`: أداة تنفيذ قابلة للتكرار تكتب `expected/actual/delta` وبصمات المصدر. الغياب يعيد رمز خروج **2**؛ الاختلاف الحسابي يعيد **1**؛ نجاح المقارنة الحسابية فقط يعيد **0**. رمز 0 لا يمنح اعتماد إنتاج.
- `scripts/fsrs-research-audit.mjs`: تدقيق منفصل على قيم الحاسبة البحثية السابقة. لا يسميها Golden Vectors للمكتبة.

## التشغيل الفعلي وحدوده

البيئة: macOS arm64، Node v24.22.1 المحلي، Vitest 3.2.4. شُغّل:

```sh
node node_modules/vitest/vitest.mjs run src/conformance src/core/fsrs.test.ts --reporter=json --outputFile=docs/05b/evidence/fsrs-tests.json
node scripts/fsrs-research-audit.mjs
node scripts/fsrs-conformance.mjs
```

النتيجة: **53/53 اختبار وحدة ناجحًا، صفر فشل وصفر تجاوز**: 20 اختبار FSRS السابق و33 اختبار مقارنة/سلامة بايتات جديدًا. المرجع المصطنع في اختبارات أداة المقارنة معلن داخلها؛ لا يُحفَظ كحزمة upstream ولا كدليل G02. تدقيق الحاسبة: 24/24 مقارنة ناجحة. تشغيل أداة مطابقة المكتبة: **0 مقارنة مرجعية ناجحة، 0 مقارنة مرجعية فاشلة، 23 حالة محجوبة، 0/12 فئة مرجعية منفذة، ورمز خروج 2**. ليس هذا «اجتيازًا للمطابقة».

جُرّب `tsc -b` أثناء عمل الوحدات المتوازية؛ أخفق حينها بسبب استيراد `LEARNING_VERSIONS` من `backup.ts` و`backup05b.test.ts` قبل إضافة المصدّر المشترك. لم يبلّغ أخطاء من ملفات هذه الإضافة. الحكم على typecheck الشامل يؤخذ من تشغيل التسليم النهائي لدى المسؤول عن الدمج، ولا يُستبدل بهذا الفحص الجزئي.

## استكمال المطابقة دون إعادة بناء التطبيق

1. في بيئة شبكة مسموحة، استرجاع npm metadata للإصدار **5.4.2** وملف tgz المحدد فيه من الناشر، مع التحقق المستقل من الالتزام والرخصة وSRI. لا تكفي صفحة معادلات أو بايتات من `main`.
2. حفظ ملفي metadata وtgz الأصليين وتشغيل التجهيز محليًا في مجلد جديد:

```sh
node scripts/fsrs-reference-prepare.mjs registry.json ts-fsrs-5.4.2.tgz /tmp/mulazama-ts-fsrs-5.4.2
node scripts/fsrs-conformance.mjs --reference /tmp/mulazama-ts-fsrs-5.4.2/package --receipt /tmp/mulazama-ts-fsrs-5.4.2/receipt.json
```

3. مراجعة `expected/actual/delta` وحفظ نتائج upstream كتثبيت ذهبي مستقل ذي بصمة، ثم إعادة تشغيله. تحديد أي فرق: تقريب/حدود/اختلاف API/سياسة وقت/خطأ تنفيذ. عدم تعديل المتوقع لإخفاء الاختلاف.
4. إن استلزم القرار استبدال التنفيذ البحثي بمكتبة، يصدر إصدار خوارزمية جديد وتجرى مقارنة replay وسجل فروق؛ لا تعاد كتابة النتائج التاريخية بصمت. يؤخذ اعتماد مسؤول المحرك والتحقق الحسابي قبل توقيع دليل G02.

**لا توجد حاليًا Golden Vectors مستقلة المصدر من حزمة 5.4.2، أو اعتماد مكتبة، أو موافقة علمية بشرية. التوصية الملزمة لهذه البوابة: استمرار الحجب.**
