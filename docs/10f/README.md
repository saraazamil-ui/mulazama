# 10-F — قارئ قابل للتجربة ومراجعة مصدر حفص المثبّت

يفصل مسار المعاينة بين **مراجعة صفحات حفص المرشحة** وبين **تجربة الحفظ والمراجعة بمواد صناعية**. في وضع مراجعة المصدر يمكن تصفح الصفحات واختيار مقدار وحفظه للمراجعة؛ لا يُنشئ الاختيار وحدات قرآن أو أحداث تعلم. وضع التجربة يستخدم مواد غير قرآنية وسجل IndexedDB مستقلًا تحت `mulazama-reader-preview-10f-*`، ويتيح اختبار اتصال القارئ بالخطة والجلسة دون اعتماد المصحف. الدخول العادي للتطبيق يظل محكومًا ببوابات المحتوى.

## المصدر الذي تستعمله مراجعة الصفحات

المرشح المختار صراحةً هو [Quran.ws — hafs-kfqc، الإصدار v1.1.1](https://github.com/quran-ws/quran-svg/releases/tag/v1.1.1)، وليس أرشيف Quranpedia السابق. ثُبّت على commit `3ff27b46cecb0c0519d77531d9c868a579d1f623`؛ لم تُنزّل الروايات الأخرى ولم يُعَد تنزيل `hafs.zip` السابق.

| الأصل | الحجم بالبايت | SHA-256 |
|---|---:|---|
| `hafs-kfqc-svg.zip`، asset `564379747` | 121,647,518 | `5d5e29eae66d9353dd8e0e51af4274c7768f81f722414b538dfd7c8de014fc91` |
| `hafs-kfqc-json.zip`، asset `565017699` | 492,327 | `27dd192cec6b5f919ffd6e7df5216464aa57a671e326fc1a37a9d82dee3f6c13` |

طابقت بصمتا ZIP القيم المنشورة في GitHub، وطابقت بايتات جميع **722 SVG و724 JSON** بصمات Git في commit المثبّت. هذه 604 صفحات أصلية و118 نسخة مقسمة حسب السورة لكل صيغة، إضافة إلى فهرسي `surah.json` و`markers.json`. جميع CRC اجتازت القراءة الكاملة. [سجل المصدر المختصر](evidence/source-pin.json) يحفظ المعرفات والبصمات وروابط التنزيل وإشعارات الحقوق.

GitHub يعلن `immutable=false` لهذا الإصدار؛ لذلك لا يكفي اسم tag وحده. manifest الكامل المولد محليًا محفوظ خارج Git في `/workspace/quran-svg-10f/manifest.json`، وبصمته `67ea17c188a0bf3763af515a6da07ce3b4d609b9f3d82751156d3b291b7d5ee1`. يحتوي SHA-256 لكل ملف وربطه بكتلة Git والأصل. **ليس manifest منشورًا من المصدر**: أعاد رابط CDN المعلن و`latest.json` حالة 404، ولا يوجد manifest في شجرة commit المختارة. تتطلب إعادة الاستلام مطابقة هذه القيم قبل الاستخدام؛ لا يُستبدل `main` بالـcommit المثبّت.

## ما اجتاز الفحص وما يعنيه للقارئ

اجتاز **722/722 SVG، بما فيها 604/604 صفحة أصلية** فحصًا ثابتًا بنمط صريح `quran-ws-hafs-kfqc-v1.1.1`، واجتاز 724/724 JSON فاحص الأرشيف. [نتيجة SVG](evidence/svg-security-summary.json) و[نتيجة JSON](evidence/json-security-summary.json) تحفظان حدود الفحص وبصمات الأدوات. لا تتضمن هذه النتائج اعتمادًا علميًا أو تصريح تشغيل جلسات القرآن.

السياسة العامة الافتراضية لـ10-D تظل صارمة: لا تستنتج النمط من الملف. التوسعة الصريحة تقبل فقط metadata المقاسة: `xml:space` في الجذر، زوج إحداثيات عددي محدود على `g`، وثلاثية `surah/ayah/number` كاملة ومتوافقة على `path` مع منع التكرار. تبقى قواعد منع السكربتات والأحداث والمراجع الخارجية والمعرفات غير الصالحة وحدود الموارد قائمة. لم تُحذف خصائص من الأصل أو تُعاد كتابة الصور لتمريرها. الأرشيف القديم ما زال مرفوضًا بسبب معرفين غير صالحين في الصفحتين 305 و577؛ [إيصال الرفض](evidence/old-source-rejection.json).

تطابقت هوية **6236 آية فريدة عبر 604 صفحات و114 سورة** في JSON وSVG، دون مفقودات أو تكرار في مجموعة الصفحات الأصلية. طابقت 6224 منطقة بيانات مسار `MLZ` حرفيًا، وطابقت 12 منطقة افتتاحية ترتيب نقاطها. [تفاصيل الخريطة](evidence/canonical-map-summary.json) لا تساوي مراجعة بصرية لكل آية. يستخدم الربط `surahNumber/ayahNumber` من JSON الصفحة، لا ترتيب العناصر أو أقرب علامة. حقل `markers.json.ayah` فهرس عام 1–6236؛ تختلف إحداثياته عن JSON الصفحة في 6115 سجلًا، ولذلك لا يُعامل كرقم آية داخل السورة أو بديل لمنطقة الاختيار.

يلزم احترام أصل `viewBox` السالب في الصفحتين 1 و2 (`-53.3109 -198.4777 345 550`)، والحفاظ على الأجزاء المنفصلة من المنطقة وعدم وصلها كشكل واحد. نجاح تطابق الإحداثيات بين ملفين لا يثبت وحده انطباق المنطقة على الحروف المطبوعة. تبقى الصور الأصلية محفوظة، وعرضها واختيار المقدار لا يغيّران بيانات التعلم.

## لماذا لم يُعتمد نص للتعلم بعد

الفروق **6235/6236** تخص مقارنة النص في أرشيف Quranpedia السابق بـ`mushafs-1.json` المرفق؛ لا تصف اختلافًا بين نصين من إصدار Quran.ws الجديد، ولا تُستخدم لاختيار نص تشغيل له. [التحليل المختصر](evidence/text-difference-summary.json) يثبت أن المشكلة ليست تلف ترميز فقط:

- نص واحد مطابق أصلًا؛ 12 اختلافًا يفسره `U+FEFF` وحده، ولا حالة إضافية يحلها NFC وحده.
- 476 حالة تتساوى في عرض تشخيصي يحذف مجموعة محددة من الضبط وعلامات الوقف والمسافات، و710 إضافية بعد طي ألف الوصل؛ هذه عمليات فقد معلومات للتشخيص في الذاكرة، ولم تُطبّق على الأصول.
- تبقى 5037 حالة تشمل الرسم والحروف الصغيرة والهمز والمدود وحدود الكلمات. هذا عدد حالات مراجعة، وليس عدد أخطاء قرآنية مثبتة. اختلف تسلسل علامات الوقف في 324 آية، وعدد المقاطع المفصولة بمسافات في 367 آية.

لا يوجد نص مختار آليًا أو اعتماد لحدود الكلمات و`token IDs`. لا يجوز إقران الكلمات بحسب مواضع `split` أو تحويل فروق الضبط إلى مساواة علمية. لذلك تظل جلسات القرآن الحقيقي محجوبة حتى اعتماد النص والطبعة وربط الكلمات والوحدات؛ اتصال الخطة والجلسة القابل للتجربة يعمل على المواد الصناعية المستقلة.

## التشغيل والتحقق

مسار المعاينة مستقل في `reader-preview.html` و`vite.reader-preview.config.ts`. تشغيله محليًا يكون بوضع `test` وعلى loopback؛ سياسة المصدر تحصره محليًا أو في رابط المعاينة الخاصة المحدد. `pnpm test:reader-preview` يشغّل اختبارات هذا المسار. `pnpm build` يظل بناء التطبيق العادي المحكوم ببوابات المحتوى، و`pnpm build:reader-preview` هو أمر بناء المعاينة المنفصلة.

هذه الوثيقة تسجل التنفيذ والأدلة المحددة أعلاه؛ لا تعلن نجاح اختبارات التسليم النهائية أو نشر إصدار جديد. يُسجل رابط المعاينة ورقم الإصدار بعد التحقق من النشر في سجل التسليم. لا نشر على `mulazama.com`، ولا تغيير لـFSRS أو سجلات المستخدمين أو النطاق الرسمي ضمن هذا العمل.

الملفات في [فهرس الأدلة](evidence/index.json) ملخصات محدودة مع بصمات تقاريرها المحلية الأصلية. لا تحتوي أصول ZIP أو SVG أو نص القرآن أو تقرير أعضاء كاملًا. المصادر الكاملة خارج Git، ووجود مسار محلي لا يضمن بقاء ملفات البيئة لاحقًا.
