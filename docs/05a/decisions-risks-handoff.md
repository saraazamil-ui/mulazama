# MULAZAMA — Phase 05-B Decisions, Risks and Engineering Handoff

التاريخ: 5 نوفمبر 2026، بتوقيت الرياض. هذه وثيقة أعمال وقرارات للاستكمال، ولا تستبدل **Engineering Readiness Report** أو تمنح إذن إطلاق. الهوية: **مُلازَمَة — MULAZAMA**. النطاق `mulazama.com` مستهدف فقط؛ لم يشتر أو يسجل أو ينشر عليه المشروع.

## ما يُسلّم للاستكمال

المشروع تطوير للمصدر السابق React/TypeScript، مع الحفاظ على المكونات وواجهات S01–S19 واستبدال حدود المنتج بوقائع وخدمات حقيقية للإعدادات والتصريحات والتفضيلات والنسخ. خدمة HME قابلة للتنفيذ والاختبار على وحدات صناعية، ومفصولة عن الواجهة ومنافذ المنصة. جلسات القرآن غير مفعلة، ولا توجد حزمة نص أو صوت معتمدة. التفاصيل القابلة للتتبع في [العقود](contracts.md) و[مصفوفة R01–R30](requirements.md).

نتيجة Vitest النهائية المحفوظة في [unit-results.json](unit-results.json): **299/299، بلا فشل أو تعليق**. تشمل المكونات 30، وخدمة التعلم 16، وخدمة المنتج 11، والتحقق 75، وHME 65، وFSRS 20، والنطاق/الحالة 33، والمحتوى 7، والنسخ 13، والمخزن المرجعي 18، والمنصة 10، وقياس المضيف 1. لا تضاف إليها التشغيلات المستهدفة الأقدم المتداخلة. المراجعة المستقلة نفذت **21/21 إعادة إنتاج** منفصلة عن عدد Vitest، وفق [peer-review.md](peer-review.md).

البناء النهائي أنتج JavaScript بحجم 332.96kB وCSS بحجم 23.94kB. وُلّد Service Worker وبيان يحتوي أربعة أصول للغلاف المحلي. هذه نتيجة بناء، ولا تثبت الفتح البارد دون اتصال؛ اختبار ذلك مكتوب وتوقف قبل التنفيذ بسبب منع localhost على 4174. فحوص IndexedDB الاثنا عشر، واختبارات المتصفح/E2E/axe، وبناء/تشغيل iOS وAndroid لم تنفذ بنجاح في هذه البيئة.

تستمر الأعمال المستقلة عند تعذر اعتماد خارجي، مع بقاء الوظيفة المرتبطة به مغلقة. اعتماد محتوى أو غلق conformance لا يتجاوز بوابة فقد بيانات أو خطأ قياس حرج. ينبغي إعادة تشغيل الاختبارات المتأثرة بعد كل تغيير، مع حفظ بصمات المصدر والنتائج الفعلية دون تحويل “مكتوب” إلى “منفذ”.

## الوظائف المؤجلة صراحة

- اعتماد وإدراج النص والخرائط والخط والصوت المرجعي والتفسير إن اعتمد في النطاق.
- تفعيل جلسات القرآن وربط C05–C09 بواجهة التعلم، ودمج إسقاطات المنتج والتعلم تحت حدود واحدة متوافقة.
- مطابقة مكتبة FSRS مستقلة وتقرير اختلافات binary64/rounding/حدود/time policy.
- توليد مهام واستحقاقات وإحصاء كلمات من المحتوى والتاريخ الفعلي؛ ربط سجل اتصال كامل وإدارة الوحدات وإصداراتها.
- اختبار IndexedDB والمتصفح/الإتاحة/العمل البارد دون اتصال؛ الأجهزة والانقطاعات الواقعية.
- native builds ومنافذ SQLite/secure keys/audio/files/notifications.
- نموذج توقع مفعّل ومعاير؛ التسجيل الشخصي الاختياري؛ تحقق تلاوة آلي أو مستقل.
- هجرة متعددة الإصدارات وخطة تحديث/رجوع محرك ومحتوى معتمدة؛ قياسات NFR وUX البشرية.

## تعليمات تشغيل وفحص للتسليم التالي

من مجلد المشروع، في بيئة Node/pnpm متاحة:

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
pnpm verify:build
pnpm security:check
pnpm test:e2e
pnpm test:offline
pnpm readiness:production
```

`readiness:production` يعيد exit غير صفري حاليًا لأن بوابات الإنتاج مفتوحة؛ هذا سلوك مقصود موثق. يجب تشغيل اختبارات IndexedDB الاثني عشر وفق [persistence.md](persistence.md)، ثم إضافة فحوص المنصات بعد إنشائها. أوامر iOS/Android غير موجودة ولا تُعرض باعتبارها جاهزة.

لم يُنشر المشروع أو يُشتر نطاق أو تنفذ عملية مالية. أي طلب نشر/شراء/إطلاق مستقبلي إجراء منفصل عن هذا التسليم البرمجي.
