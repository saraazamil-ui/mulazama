# النشر والتراجع القابل للمراجعة — 06-L2

**لا أمر نشر إنتاجي في هذا التسليم.** الأوامر الآتية محلية فقط، لا تحتاج حسابًا أو سرًا ولا تفتح بوابة جلسة. راجع حالة القرار في Final-Report.md قبل أي استخدام آخر.

## إعادة الاختبارات وبناء المعاينة

من جذر النسخة المستعادة، مع Node24+ وpnpm11.25.0 وPython3 وOpenSSL:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
python3 scripts/verify-06l2.py --browser
```

بديل Chrome المثبت: `PW_CHANNEL=chrome python3 scripts/verify-06l2.py --browser`. تتضمن الحزمة subset مبصومًا من dist الأصلي L1 في references/06l1-preview-baseline، محصورًا في تمرين التراجع. يتحقق الاختبار من receipt المثبت ثم كل بايت؛ لا يلزم تحميل الإصدار السابق ولا تشغيل حساب خارجي. التبعية للمرجع FSRS محفوظة بإصدارها الرسمي ومثبتة بتوقيع registry/bصمات محلية، وليس المرجع مولدًا من محرك المشروع.

لإنشاء معاينة تفاعلية بعد البناء الناجح، انسخ قيمة sourceDigest من خرج `node scripts/generate-release-context.mjs` (أو final-source-context.log) إلى الحقل التالي:

```sh
node scripts/local-preview-06l2.mjs create --id l2-review --source-digest DIGEST_FROM_VERIFIED_BUILD
node scripts/local-preview-06l2.mjs select --id l2-review --expected none
node scripts/local-preview-06l2.mjs serve --port 4180
```

`DIGEST_FROM_VERIFIED_BUILD` موضع قيمة وليس سرًا ولا أمرًا صالحًا كما هو. ترفض الأداة قيمة غير صحيحة أو لا تظهر داخل البناء. افتح العنوان127.0.0.1 الذي تطبعه الأداة. تستمع محليًا فقط. ينهي Ctrl+C الخادم. يمكن TLS محليًا بــ`--cert /path/to/local.crt --key /path/to/local.key`؛ لا تودع مفاتيح في Git ولا تعدّل ثقة الجهاز لهذا الغرض.

كل إصدار في مجلد مستقل، بلا استبدال صامت. لاختيار إصدار جديد استعمل `select --id next-id --expected l2-review`. يعيد `select --id l2-review --expected next-id` النسخة السابقة بعد تثبيت بصمتها المسجلة؛ تعديلها بعد اختيارها يرفض التراجع. التراجع يبدل أصول التطبيق فقط ولا يعيد كتابة IndexedDB أو يزيل أحداثًا.

## ما أثبته الاختبار الفعلي

L2DEP01 اختبر HTTPS محليًا بشهادة ذاتية مؤقتة داخل سياق اختبار يقبلها فقط، وheaders ورفض ملفات المصدر والمسارات والكتابة. L2DEP02 عمل على HTTP loopback الذي يسمح بـSW؛ حدّث L1 إلى L2 ثم تراجع L1 على نفس الأصل، بعد إغلاق التبويب وانتظار عامل الخدمة الفعلي. قارَن بصمات الصفوف المشفرة والتفضيلات والحجب وأعاد التحميل دون اتصال في الاتجاهين. جميع البيانات صناعية في profile جديد؛ لا بيانات مستخدم حقيقي.

جرى فصل اختبار TLS عن SW لأن Chrome رفض تثبيت عامل خدمة بشهادة ذاتية غير موثوقة؛ هذا الرفض صحيح، وليس مبررًا لتعطيل التحقق من شهادة عامة. يحتفظ Test-Report.md بالمحاولات السابقة. لا يثبت الاختبار شهادة mulazama.com أو CDN أو ترحيل FSRS أو استعادة بعد تلف جهاز.

## إجراءات المزود بعد الحساب والتفويض

1. عيّن مرشحًا محددًا بالcommit وsourceDigest ونسخة ZIP، واستوف أدلة البوابات وتوقيعاتها في السياق الصحيح. افصل تطويرًا ومعاينة وإنتاجًا، ومنع auto-deploy للإنتاج قبل الموافقة.
2. أنشئ معاينة محمية فقط بعد إذنها، وطبّق headers/types/cache على المزود. احتفظ بآخر artifact صالح ومراجعة المصدر وتقاريرها خارج مسار الاستبدال.
3. اختبر رحلة حقيقية لكل فئة، الهاتف وTLS وoffline والتصحيح، ثم صدّر نسخة بيانات اختبار مشفرة وتحقق من استعادتها على نفس المرشح. لا تنقل سجلات المشاركين الخام إلى CI.
4. نفّذ تحديثًا وتراجعًا على نفس أصل staging، مع tabs/SW ونسخة بيانات ثابتة؛ قارن الأحداث قبل وبعد، ثم اختبر reload/offline. لا تمسح التخزين لإصلاح تحديث.
5. إن احتاج تغيير المحرك ترحيلًا، اربط الخطة بنتائج أداة fsrs-transition06l2 وبنسخة بيانات وتفويض صريح. الكود الحالي لا ينفذ هذا الترحيل.
6. عند فشل التحديث أوقف تعميمه، أعد artifact السابق عبر المزود، تحقق من health/bصمة المصدر والقراءة والاستئناف، واحفظ تقرير الحادث دون بيانات خاصة. لا تغير DNS لإخفاء العطل ولا تحذف قاعدة الحافظ.
7. لا production حتى اكتمال تجربة10–20 وحل الحرج وموافقة نشر واضحة؛ تحفظ هوية الموافقة وسياقها وبصمة البناء، ولا تفترض أن CI يمنحها.

## حفظ تاريخ المصدر

الحزمة المصاحبة `MULAZAMA-Phase-06L2-Source-History.bundle` تحتوي تاريخ E1 وL1 وفرع L2. مثال الاستعادة في مجلد جديد:

```sh
git clone -b release/06-l2 MULAZAMA-Phase-06L2-Source-History.bundle mulazama-restored
git -C mulazama-restored fsck --full
```

يرجع L1 محليًا باختيار فرع develop في نسخة منفصلة، دون reset للسجل العامل أو قواعد المستخدم. عند إنشاء مستودع بعيد مخول مستقبلًا: ارفع التاريخ بعد مراجعة محتواه، واحم main بمراجعة وCI ومعاينة. ربط workflow موجود محليًا؛ تشغيله على GitHub وحماية الفروع لم يحدثا دون حساب.
