# جاهزية الاستضافة والنطاق — 06-L2

**المعاينة الهندسية المحلية منفذة؛ الاستضافة الخارجية والنطاق والبريد غير مجهزة فعليًا.** المالكة هي المشغلة ومن السعودية، ولم تنشئ حسابات بحسب آخر إفادة. لا نفترض وجود مستودع بعيد أو مزود أو إثبات ملكية أو قناة دعم عامة.

| البند | المنفذ والدليل | المتبقي |
|---|---|---|
| البناء | Vite بإصدارات مقفلة؛ فحص أصول RTL وPWA ومنع تصريح الاختبار من حزمة المنتج | توقيع مرشح إصدار بعد إغلاق البوابات |
| المعاينة | خادم loopback وأصول مبصومة وقفل تحديث وتحقق بصمة عند التراجع | استضافة معاينة مخولة، مقيدة الوصول ومختبرة |
| HTTPS | اختبار محلي بشهادة ذاتية مؤقتة وفحص CSP/headers | شهادة موثوقة على النطاق واختبار جهاز الهدف؛ لم تُصدر شهادة عامة |
| التحديث والتراجع | L1→L2→L1 على أصل متصفح واحد، مقارنة صفوف IndexedDB المشفرة، offline في الاتجاهين | تمرين المزود الفعلي بعد اختيار الحساب؛ لا يدعي التمرين ترحيل المحرك |

| الدعم | صفحة محلية تعمل offline ولا ترسل سجلات | قناة فعلية، مسؤول ومدة استجابة وإجراء حادث |

## بيئات الإصدار

التطوير `pnpm dev` على127.0.0.1؛ المعاينة المحلية `scripts/local-preview-06l2.mjs` بأصول محددة وبصمة مصدر؛ الإنتاج المستهدف `https://mulazama.com` غير منشأ. لا ملفات أسرار ولا اتصالات مزود في الأدوات الجديدة. يحتفظ Git بفروع الأصل والتطوير وفرع L2؛ origin في هذه النسخة يشير إلى bundle محلي، وليس GitHub أو خادمًا بعيدًا.

يلزم مزود أصول ثابتة يدعم HTTPS وheaders وسياسة cache ونسخًا قابلة للاسترجاع ومعاينات مقيدة. لا تحتاج البنية الحالية قاعدة بيانات خادم: سجل الحافظ على الجهاز؛ المزامنة والحسابات ليستا وظيفة منفذة. لا يُرفع إلا dist للمعاينة المخولة بعد الإذن؛ لا محتوى المراجعة المحجور أو references أو تقارير أو مفاتيح. تنفيذ CSP الفعلي في الخادم المحلي يطابق template في deployment/headers.example. يجب إثبات تطبيق نظيره على المزود، لا الاكتفاء بوضع الملف في المستودع.

إذا اختارت المالكة Cloudflare Pages، توضح وثائقه أن ربط النطاق الجذري يحتاج zone وnameservers، وأن النطاق الفرعي يحتاج CNAME إلى اسم المشروع الفعلي بعد إضافته في لوحة Pages. لا يوجد اسم مشروع أو قيمة DNS صالحة لإعطائها الآن. [توثيق النطاق الرسمي](https://developers.cloudflare.com/pages/configuration/custom-domains/).

معاينات Pages تكون عامة افتراضيًا؛ يلزم تقييدها عبر Access قبل إعطاء الرابط للمشاركين، مع اختبار الرابط غير المصرح له. هذه ملاحظة خاصة بالمزود وليست اختيارًا أو إعدادًا نُفذ. [توثيق المعاينات الرسمي](https://developers.cloudflare.com/pages/configuration/preview-deployments/).

البريد يحتاج نطاقًا متحققًا وعنوانًا فعليًا وفق مزوده؛ وجود إعادة توجيه وحدها لا يثبت صندوق دعم أو صلاحية إرسال من عنوانه. راجع وثائق الخدمة المختارة واختبر كلا الاتجاهين. [توثيق Cloudflare Email Service الحالي](https://developers.cloudflare.com/email-service/get-started/). لا توصية شراء أو ادعاء مجانية أو إنشاء حساب ضمن التسليم.

إعداد القانون والخصوصية مسودة حتى اعتماد الغرض والبيانات والموردين والاحتفاظ والحقوق والتحويلات إن وجدت. راجع [تقرير الأمن والخصوصية](Data-Security-Privacy.md). يلزم موافقة مستقلة قبل الإنتاج، ولا يجعل نجاح CI أو صدور رابط معاينة الإطلاق مخولًا.
