# التشغيل والتحديث والتراجع — 06-L4

**لا نشر إنتاجي في هذا التسليم.** المصدر المحلي على `release/06-l4` من تاريخ L3 المثبت، وسجل Git المسلّم يعيد النسخ السابقة. المستودع الخاص الموجود يحفظ هوية المشروع منفصلة حتى استيراد التاريخ ومراجعته؛ لا force-push أو استبدال main. أُعد فرع توثيقي ومراجعة للنطاق فقط. يلزم نقل تاريخ التطبيق عبر Git مصادق عليه مع الحفاظ على brand و operations، ثم فرع develop ومراجعة إلى main وحماية الفرع وفحوص QA إلزامية. لا يكفي تفعيل ملف CI محلي للادعاء بأنه نُفذ على GitHub.

## استعادة سجل الشفرة

من المجلد الذي يحتوي ملف bundle المسلّم، أنشئ مجلدًا جديدًا؛ لا تنفذ ذلك فوق مشروع قائم:

```sh
git clone -b release/06-l4 MULAZAMA-Phase-06L4-Source-History.bundle mulazama-restored
git -C mulazama-restored fsck --full
git -C mulazama-restored switch -c develop
```

يحتفظ السجل بمرجع `release/06-l3` وبأسلافه. يمكن فتح نسخة منه في checkout مستقل للمقارنة؛ لا تشغّل قارئًا أقدم على قاعدة أحدث دون تحقق التوافق. يشمل التسليم إيصال فحص مستقل للحزمة وGit، ولا يتضمن ملف bundle بيانات متصفح المستخدمين. استعادة الشفرة لا تستعيد تلقائيًا ملف بيانات الحافظ؛ لذلك توجد وظيفة النسخة المشفرة داخل التطبيق.

## إعادة التحقق محليًا

Node24+ و pnpm11.25.0 و Python3 و OpenSSL. من جذر المشروع:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
python3 scripts/verify-06l4.py --browser
```

عند استخدام المتصفح المؤقت لهذه الجلسة: `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/mulazama-06l4-browser` مع عدم تحديد `PW_CHANNEL=chrome`. الجهاز الآخر ينزل متصفح Playwright الخاص به. لا تضم الحزمة node_modules أو المتصفح أو بيانات اختبار عابرة. `pnpm engineering:local` يشغل المادة الصناعية على loopback فقط؛ يمنع رفع dist-engineering.

## معاينة إصدار ثابت

تعمل أدوات `scripts/local-preview-06l2.mjs` باسمها التاريخي: create ينشئ artifact من dist، select يبدل بشرط expected، serve يعمل على 127.0.0.1 فقط. استخدم بصمة المصدر من `src/release/build-context.generated.ts`. لا تستخدم أداة المعاينة كخادم عام. خيار serve `--maintenance` يقدم صفحة 503 مع Retry-After، و 404 يعمل حتى دون اتصال. حالة 503 لا تمحو التخزين ولا تسحب نسخة offline مثبتة سابقًا.

اختبار L4DEP02 نفذ L3→L4→L3 في الأصل نفسه وقارن الصفوف المشفرة حرفيًا والإعدادات والجلسات المحجوبة والعمل دون اتصال. خط الأساس dist الأصلي داخل `references/06l3-preview-baseline/` مثبت ببصمة ZIP الأصلي وإيصال. لا إعادة بناء تعيد تسمية إصدار جديد بأنه قديم. HTTPS المستخدم في الاختبار شهادة مؤقتة محلية؛ لا ادعاء TLS للنطاق الخارجي.

## النشر اللاحق بعد الاعتماد

1. اختر المضيف وحساباته وبيئتين منفصلتين؛ لا تضع أسرارًا في VITE_* لأنها تصبح عامة. النسخة الحالية لا تحتاج مفاتيح API أو حساب تعلم.
2. استورد الشفرة بتاريخها دون الكتابة على هوية المشروع، وشغل CI والمراجعة على commit محدد. لا رفع تلقائي قبل تفعيل حماية كل عناوين المعاينة.
3. انشر artifact المعتمد في معاينة مقيدة، وأعد الرحلتين بقرآن معتمد و offline والاستعادة والأمان. تحقق من CSP و TLS و cache والأخطاء ومراقبة محدودة دون سجلات تعلم.
4. بعد التجربة البشرية وإغلاق الحرج، اعرض للمالكة commit وبصمة artifact ورابطالمعاينة والنتائج والمخاطر واطلب إذن النشر النهائي. عندئذ فقط تُعتمد تغييرات DNS والإنتاج.
5. احفظ artifact و Gitbundle والإعدادات السابقة ونسخة بيانات مشفرة اختبارية؛ تبديل artifact لا يرحل IndexedDB. افحص توافق القارئ مع السجل قبل أي تراجع، ولا تحذف قاعدة المستخدم. قارئ L2 لا يقبل السجلات المصححة. عند عيب بيانات أوقف الكتابة واحفظ الأصل للتحقيق بدل إعادة وسم الأحداث.

التراجع الخارجي لم يُنفذ لأن المضيف غير مختار؛ التمرين المحلي ناجح وحدوده موثقة. [حالة التشغيل](Hosting-Readiness.md)، [أمن البيانات](Data-Security-Report.md).
