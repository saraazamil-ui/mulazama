# التشغيل والتراجع — 06-L3

النتيجة المسموح بها حاليًا معاينة محلية وهندسية فقط. لا نطاق مثبت أو استضافة خارجية أو HTTPS عام. [جاهزية الاستضافة](Hosting-Readiness.md).

1. ثبّت الاعتماديات بالقفل ثم نفّذ `python3 scripts/verify-06l3.py --browser` من جذر المشروع. نتيجة فحوص البوابات المحجوبة لا تسمح بالنشر.
2. `pnpm engineering:local` يبني الرحلة الصناعية ويخدمها على `127.0.0.1:4178` فقط. لا تنقل هذا البناء إلى استضافة، ولا تدخل بيانات حافظ فعلي فيه.
3. `pnpm build` يبني المدخل العادي. أوامر `preview:release` أدناه تجهز المعاينة المحلية المحمية. راجع خيارات [الخادم القائم](../../scripts/local-preview-06l2.mjs)؛ الحزمة لا تنفذ شراء أو DNS أو نشرًا.
4. التجربة القرآنية تتطلب حزمة المحتوى الموقعة والكتالوج وسياسة الوقت واعتمادات سياق الإصدار، واختيار `reference-06e1` صريحًا لسجل جديد. لا يكفي تغيير متغير بيئة أو حقل اعتماد إلى true. إدخال الحزمة إلى `runtimeJourneyInput` يستلزم إعادة بناء الأدلة والتوقيع على المصدر النهائي؛ هذه النسخة تبقيه null.
5. عند إتاحة الاستضافة لاحقًا، اتبع [إعدادات التشغيل القائمة](../06l2/Deploy-and-Rollback.md) مع هذه النسخة، ثم تحقق من TLS وDNS والعناوين والدعم في البيئة الفعلية. لم تُختبر تلك الخدمات هنا.

لنسخة معاينة محلية جديدة بلا حالة سابقة، تنفذ هذه الأوامر بعد البناء:

```sh
pnpm preview:release create --id l3-local --source-digest 99db11ff0766b099f6f10b8e66ac250717f492926ad2deab33f3699fdfd54e54
pnpm preview:release select --id l3-local --expected none
pnpm preview:release serve --port 4180
```

بعد إعادة بناء شفرة معدلة، استخدم بصمة ذلك البناء الجديدة ولا تنسخ البصمة أعلاه. الخادم محلي فقط، و`--expected none` يرفض استبدال معاينة موجودة دون اختيار صريح.

## التراجع الذي اختُبر

اختبار المتصفح يشغل L2→L3→L2 على origin محلي ثابت، مع تطابق آثار البناء والمحافظة على **سجل عام قديم**. المرجع [L2](../../references/06l2-preview-baseline/receipt.json) مثبت ببايتات حزمة البداية، ونتائج التنفيذ النهائية في [أوامر التحقق](evidence/verification-commands.json).

السجل المصحح الجديد غير متوافق مع قارئL2: [فحص القارئ الأصلي](evidence/fsrs-backward-reader.json). يلزم الاحتفاظ بقارئL3 أو نسخة بيانات ما قبل الانتقال مع إصدارها المطابق؛ لا حذف للأحداث الجديدة أو إعادة وسمها لتبدو قديمة. لا توجد في التسليم هجرة لبيانات حقيقية، ولا أمر تلقائي يخفض نسختها.

احفظ ZIP وbundle وملف التحقق خارج نسخة العمل. لاسترجاع الشفرة في مجلد جديد:

```sh
git clone MULAZAMA-Phase-06L3-Source-History.bundle mulazama-restored
cd mulazama-restored
git checkout release/06-l3
```

تصدير سجل الحافظ يتم من واجهة البيانات بكلمة مرور؛ جرّب فحص النسخة قبل الاستعادة. لا تُحفظ كلمات المرور في الشفرة. استعادة ملف يستبدل سجل الجهاز تتطلب التأكيد الموجود في الواجهة؛ لم ننفذ استبدالًا لبيانات مالكة المشروع أو مستخدمين.
