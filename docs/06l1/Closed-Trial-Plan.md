# بروتوكول تجربة مغلقة — محدد قبل التنفيذ

الحالة: لم تُجرَ تجربة بشرية ولم يُدعَ مشاركون. لا يبدأ هذا البروتوكول قبل إغلاق موانع L01–L15 وصدور قرار مكتوب «جاهز للتجربة» من السياق الموافق للنسخة. الحالية تصلح لمراجعة UX هندسية محلية فقط.

العينة المقترحة 10–20 بالغًا موافقًا، مع تمثيل متوازن للمبتدئين وأصحاب المحفوظات ومسار الجمع. تستبعد مشاركة القاصرين مؤقتًا حتى تعتمد سياسة مناسبة؛ هذا قيد بروتوكولي وليس ادعاء امتثال. لا إثبات إحصائي عام ولا إثبات فاعلية تربوية من هذه العينة.

## موافقة ومعلومات قبل البدء

يوضح للمشارك الهدف، أن الجلسة مراقبة بإذنه، ما سيجمع ولماذا، طوعية الانسحاب بلا عقوبة، الشخص المسؤول ووسيلة التواصل المعتمدة ومدة الاحتفاظ. لا تسجيل صوت/شاشة افتراضيًا. تستخدم رموز مشارك لا أسماء في ملف التحليل. تتلقى المالكة الموافقات في قناة معتمدة بعد تجهيزها؛ لا تجمعها هذه الشفرة. لا ترسل سجلات الحفظ الخام. تُتفق وسيلة ملاحظة اليدوية أو مشاركة الشاشة اختياريًا، وتراجع صور الأخطاء قبل حفظها.

## المهام والقياسات المسبقة

| المهمة | القياس | المستهدف الأولي |
|---|---|---|
| إعداد جديد/سابق/مختلط | إتمام بلا مساعدة، زمن، عدد تفاعلات وإعادة إدخال | 90% على الأقل؛ تقرير البسط/المقام لكل فئة |
| بدء أول ورد فعلي | الوصول لنشاط معتمد مناسب ثم بدء ناجح | 90% بلا تدخل، لا مسار يتجاوز بوابة |
| تسجيل نتيجة وتصحيح خطأ | حفظ مؤكد مرة واحدة وإعادة قراءة بعد reload | 100% سلامة أحداث؛ 90% يفهمون الفرق بين التصريح والنتيجة |
| انقطاع واستئناف | سجل محفوظ وخطوة عودة مفهومة دون عقوبة | صفر فقد أو جدولة غير مفسرة؛ 90% ينجزون المهمة |
| فائدة الورد | درجة 1–5 مع سبب مفتوح اختياري | 80% يمنحون 4 أو5؛ لا يستبدل ذلك الحكم العلمي |
| يوم7 / يوم14 | عودة اختيارية واحدة على الأقل، مقام الموافقين مع بيان المنسحبين/المفقودين | 60% /50% كمؤشر تعلم منتج، لا ضغط على الفرد |
| الخصوصية والإتاحة | فهم التخزين المحلي والنسخة، تنفيذ بلوحة مفاتيح وهاتف | صفر عائق حرج، توثيق كل عقبة |

تعريف التفاعل: تفعيل أمر أو تغيير قيمة/اختيار؛ لا تُحسب حروف الكتابة أو التمرير تفاعلًا مستقلاً. يقاس الزمن منفصلًا مع التفكير والمساعدة. تميّز التعثرات التقنية عن عدم مناسبة المهمة وعن ضعف صياغتها. لا تحول إتمام النشاط إلى نجاح استرجاع.

## جمع النتائج والقرار

نموذج لكل جلسة: رمز، الفئة، رقم الإصدار وبصمة البناء، الجهاز/المتصفح، المهمة، وقت البداية/النهاية، أفعال/مساعدات، نجاح/فشل/تعذر وسببه، رمز العطل، اقتراح المستخدم الاختياري، موافقة متابعة7/14. ترصد أسباب الانقطاع بسؤال اختياري محترم، دون إشعارات ملحّة أو مقارنات.

إيقاف فوري عند فقد بيانات أو تجاوز بوابة أو كشف معلومات أو عرض نص غير مطابق. يحفظ الأصل وتُعزل النسخة ويبدأ إجراء الحادث دون إعادة تعيين قاعدة المستخدم. إصلاح العيوب ثم اختبار انحدار وإعادة المهمة المتأثرة بموافقة المشارك. لا يتغير الهدف العددي بأثر رجعي لإعلان النجاح.

بعد14 يومًا تُنشر نتائج مجمعة بالعدد الفعلي والمتعذر والمنسحب، وتوصف القيود. أي عيب حرج يمنع الإطلاق مهما كانت النسب. عدم تحقيق مستهدف UX يستدعي معالجة محددة وقرارًا موثقًا. الانتقال للإطلاق العام يتطلب موافقة مستقلة واستيفاء بقية معايير المستخدم، لا استنتاجًا تلقائيًا من نجاح الاختبارات أو رضا العينة.
