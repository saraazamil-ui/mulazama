# مُلازَمَة — أساس ملف ذاكرة الحافظ الشخصي 06-E1

## ما أُنشئ

أضيف قارئ مشتق خالص: `projectPersonalMemory(snapshot, now)` في `src/memory/personal-memory.ts`. يتحقق من كامل سجل المنتج وHME بواسطة `replayHistory` ثم يبني ملفًا لكل وحدة مسجلة. لا ينشئ مخزنًا أو نسخة بيانات جديدة، ولا يكتب حدثًا، ولا يغيّر المصدر، ولا يمنح إذنًا لتشغيل جلسة، ولا يعرض واجهة جديدة للمستخدم.

هذه بنية أساس لفحص الأدلة المتاحة وليست نموذجًا تنبؤيًا بديلًا عنFSRS. لا تحتوي النتيجة على stability أوdifficulty أوprobability أوdue date أو مستوى إتقان. إعادة بناء HME التاريخية تُنفذ للتحقق من السجل؛ وجودها لا يجعل المحرك التاريخي معتمدًا أو يقلبه إلى التنفيذ المصحح.

## هوية الملف ومحتواه

| المجال | المصدر والمعنى |
|---|---|
| هوية الوحدة | userId + unitId + editionId + probeProfileVersionId؛ التغطية الخام باقية داخل تعريفها ولا تدمج بين الوحدات أو الطبعات |
| التسجيل | معرف وتاريخ UnitRegistered؛ يسمى تسجيل وحدة فقط |
| تاريخ الحفظ الموثق | unavailable وat:null؛ لا يوجد حدث اكتساب قرآن معتمد يثبت هذا التاريخ |
| محاولات الاسترجاع | جميع المحاولات، بما فيها غير المقيّمة والمفتوحة والمنقطعة والمعاد بدؤها، وفق هوية attemptId |
| أحدث ملاحظة | ملاحظة التقييم المعاد بناؤها بعد التصحيح، مع بقاء غير المعلوم null أوunknown |
| تاريخ التصحيحات | كل AssessmentSubmitted/Corrected بمعرف الحدث والأمر والنسخة والوقت والسبب والملاحظة المبلّغ عنها وإصدارات المصدر |
| الزمن | startedAt وendedAt ومنطقة الالتقاط، وفواصل بالملي ثانية بين بدايات المحاولات وبين بداية المحاولة وآخر تعرض ذي صلة |
| مصدر التعرض | معرف حدث التعرض الفعلي، ضمن مصادر المحاولة والوحدة؛ ويطابق timestamp الذي أنتجه إعادة بناء HME |
| المساعدة والبلاغات | hints/revealed ونهاية المحاولة وبلاغات الأخطاء المربوطة بـattemptId مع درجة يقينها كما وردت |
| هوية الأدلة | opportunityIds وclusterIds المميزة؛ تنص البنية على أنها هويات مختلفة وليست إثباتًا لاستقلال الأدلة عبر الزمن |
| كفاية البيانات | no-attempts أوunassessed-only أوobservations-present، مع عد حقول أحدث الملاحظات المفقودة؛ predictiveSufficiency دائمًاnot-established |
| الجدولة | إصدارات المصدر التاريخية فقط، وfutureSchedule:unavailable؛ عند وجود ملاحظات مؤهلة وفق السياسة التاريخية تكون الحالةrequires-explicit-rebuild |

تسمية «مؤهل» في `recordedPolicyEvaluation` تعني تقييمًا وفق السياسة المسجلة فقط، وترافقها علامة `recorded-policy-only-not-scientific-approval`. لا تُفسر بوصفها اعتمادًا لسلم تسميع أو إثباتًا لإتقان القرآن. الملف لا يقرر وحده انتخاب نسخة FSRS أو ترحيلها.

البلاغ المنتجّي الذي لا يملك مرجع وحدة معتمدًا يبقى في `unlinkedMistakeEventIds` ولا يُلصق بمقطع بالتخمين. كذلك تبقى مسودةHME ذاتattemptId:null غير مرتبطة. مصدر كل وحدة يشمل الوقائع المرتبطة بها مباشرة وتسجيل تعريفها؛ لا يدّعي دمج أهداف المنتج العامة في سجل اكتساب.

## التصحيح وعدم التكرار والوقت

التصحيح يضيف نسخة من الملاحظة داخل تاريخ المحاولة نفسها. `recordedAt` هو وقت تسجيل التصحيح و`effectiveReviewAt` هو بداية التسميع الأصلية؛ لا تصبح عملية التصحيح محاولة استرجاع جديدة. العدد `corrections` مستقل عن عدد المحاولات المقيّمة.

إعادة إرسال الأمر نفسه إلىEventStore تبقى idempotent. أما وصول لقطة خام ذات معرفات أحداث أو أوامر مكررة فيُرفض وفق العقد الصارم للتاريخ؛ القارئ لا ينظفها بصمت أو يعيد كتابتها. الإصدارات غير المدعومة، والهوية المخالفة، ونسخة تصحيح غير مطابقة، وغلاف الحدث الفاسد تؤدي إلى فشل قبل إنتاج ملف مضلل.

الفواصل هي فروق اللحظات المطلقة بالملي ثانية، لا فرق اليوم المحلي ولا زمن تسجيل التصحيح. عبور منتصف الليل بالرياض خلال دقيقتين يبقى120000 ملي ثانية، ولو اختلفت منطقة الالتقاط. لا يحول هذا القارئ الفاصل إلى أيامFSRS ولا يعيد تعريف سياسته الزمنية. المحاولات المتساوية في timestamp تحتفظ بترتيبها في المصدر بدل ترتيب يعتمد على لغة النظام.

إعادة بدء التسميع تحفظ المحاولة المنقطعة وتربط حدث الإعادة بإغلاقها وببدء الجديدة، وتبقي عدم يقين فجوة التعرض ظاهرًا. نهاية جلسة عادية بعد تسميع مكتمل لا تُفترض تعرضًا جديدًا؛ يتحقق الاختبار من بقاء معرف التعرض الصحيح.

## التحقق الفعلي وحدوده

شُغلت15 حالة مخصصة ونجحت15/15، دون فشل أو تخطٍ، في `src/memory/personal-memory.test.ts`. النتائج في `evidence/personal-memory-tests.json` و`.log`؛ لا تجمع مع عداد المجموعة الشاملة مرة ثانية.

تشمل الحالات: المستخدم الجديد، التسجيل بلا حفظ، إسناد الوقائع، حفظ سلسلة التصحيح، الملاحظات المجهولة، الانقطاع والإعادة، المناطق الزمنية، idempotency ورفض النسخة المكررة، الفساد، الحتمية وعدم مشاركة مراجع قابلة لتغيير المصدر، فصل الطبعات، البلاغات غير المرتبطة، استعادة النسخة المشفرة الكاملة، الوقت المستقبلي، وتتبع حدث التعرض.

اختبار الاستعادة يثبت بقاء الوقائع الخام وملفات الوحدات بعد التشفير والاستعادة بالمخطط نفسه؛ رقم مراجعة المخزن إيصال كتابة وقد يختلف عن الأصل، لذلك لا يُفهم تغيره بوصفه تغيرًا في حقائق الوحدة. الاختبارات صناعية بلا نص قرآني أو بيانات مستخدم شخصية، ولا تثبت جميع حالات المتصفح أو انقطاع الطاقة؛ تقرير الاختبارات النهائي يحدد نطاق المتصفح وoffline.

لا يوجد في هذه المرحلة تعريف علمي لكفاية البيانات الشخصية أو معيار اكتساب جديد أو نموذج تخصيص أوزان أو ضبط تلقائي للاحتفاظ. ما زال ربط الحفظ المكتمل بحدث اكتساب معتمد وعقد وحدة قرآن معتمد، واعتماد سلم الملاحظة ونوع النشاط، مطلوبًا قبل الانتقال من هذا الأساس إلى ذاكرة شخصية معتمدة أو توصيات للمستخدم.
