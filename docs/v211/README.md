# مُلازَمَة V2.1.1 — تجربة الرحلة الخاصة

استكمال PR #19 على `codex/v211-private-journey`، مبني على السجل الموجود وعلى وثيقة V2.1.1 المرفقة. لا يحتوي هذا المسار على نص قرآني أو حسابات إنتاجية، ولا يفتح G01–G10.

## الرابط الخاص للجوال

**[افتح معاينة مُلازَمَة البنفسجية V2.1.1](https://mulazama-preview-05a.sara-a-zamil.chatgpt.site)** بحساب ChatGPT المالك للمعاينة. الوصول خاص بالمالكة، والنسخة المستضافة 8 على Site القائم نفسه. لا تحتاج هذه المعاينة إلى بقاء بيئة Codex مفتوحة؛ بياناتها الاصطناعية تحفظ في متصفح كل جهاز ولا تتزامن مع جهاز آخر. لا تُستخدم قاعدة الإنتاج أو يُعرض النص القرآني غير المعتمد.

فُحص الرابط الفعلي: 401 لغير المصرح لهم في الصفحة وملف JavaScript، و200 للطلب المصرح به مع تطابق بصمات الأصول الأربعة. نجحت رحلة على Chromium بحجم 390×844 تشمل التوقف وإعادة الفتح والإكمال وإعادة التحميل وتصدير السجل، دون أخطاء صفحة أو طلبات خارجية أو تجاوز عرض الشاشة. الاختبار استخدم استجابات HTTPS الحقيقية عبر وكيل البيئة وصلاحية خدمة مقيدة بالأصل؛ لا يدعي اختبار هاتف فعلي أو إكمال تسجيل دخول المالكة تفاعليًا. أدلة الفحص وحدود مسار المتصفح المكتبي في `evidence/https-preview.json` و`RESUME-V211.md`.

## تجربة النسخة محليًا

```sh
pnpm install --frozen-lockfile
pnpm preview:v211
```

افتح `http://127.0.0.1:4182` **في متصفح البيئة التي تشغل الأمر**. الخادم مرتبط بالحلقة المحلية فقط؛ ليس رابط استضافة عامًا. في Codex Cloud توجد المعاينة داخل Chromium في لوحة Desktop المشتركة. يبدأ المستخدم بثلاثة مقادير اصطناعية، كل منها ثماني وحدات، ويمكنه إعلان بعضها أو البدء دون محفوظ. يحدد مدة التعاهد صراحة ثم يؤكد ملخص الخطة مرة واحدة.

جرّب الحفظ بهدفه الافتراضي 20 والتثبيت بهدفه الافتراضي 5، أو غيّرهما قبل بدء الجلسة. كل ضغطة تُحفظ قبل تحديث العدد؛ التوقف وإعادة فتح الصفحة يحفظان النطاق والهدف والعدد. التثبيت متاح عندما يوجد مقدار سابق كامل ومحفوظ ومتصل. يمكن تقديم **وقت التجربة فقط** من أعلى المعاينة إلى الجمعة ثم السبت لاختبار لقطة المراجعة وأهلية التعاهد؛ يبقى التاريخ التجريبي محفوظًا عند إعادة الفتح.

من التعاهد يمكن تسجيل المقدار كاملًا أو جزئيًا، ومنه وحدات محددة متفرقة. تبقى الأجزاء الأخرى على استحقاقها، ويظهر اقتراح موعد للمنجز فقط يحتاج تأكيدًا أو تعديلًا. تعديل الخطة يعرض فرق المواعيد قبل تأكيده، ويحفظ المواعيد اليدوية والسجل السابق. تنزيل الملخص يحوي الأحداث والإيصالات والإسقاط وoutbox المعلق؛ ليس نسخة سحابية ولا يتيح استيرادًا عامًا.

## مواضع التنفيذ وحدوده

| المسار | الوظيفة |
| --- | --- |
| `src/application/product-v211.ts` | أحداث `mulazama.product.v2.1.1` وإعادة الإسقاط ولقطات الجلسات والجمعة والتعاهد |
| `src/persistence/product-v211-store.ts` | معاملة IndexedDB واحدة للأحداث والإسقاط والإيصال وoutbox، ومنع التكرار وتعارض الإصدارات |
| `src/V211App.tsx` و`src/v211.css` | الإعداد واليوم والحفظ والتثبيت والأسبوع والتعاهد والتقدم والمصحف المحجوب والإعدادات |
| `src/testing/v211.tsx` | مدخل معاينة خاص منفصل، لا يفتح قاعدة legacy ولا ينشئ صلاحية عرض قرآن |
| `src/testing/V211Preview.tsx` | تقديم التاريخ الاصطناعي للتجربة فقط، خارج رحلة الإنتاج |
| `scripts/preview-v211.mjs` | بناء منفصل، فحص الأصول وحجب النص الخام وخادم محلي بقائمة ملفات محددة |
| `src/testing/v211-preview-origin.ts` | قصر التشغيل على الحلقة المحلية أو أصل HTTPS محدد وقت البناء، دون أعلام تفعيل من URL أو التخزين |
| `scripts/package-v211-site.mjs` | حزمة Worker بأصول اصطناعية مثبتة البصمات فقط، دون ربط قواعد بيانات أو تضمين شجرة المستودع |
| `content/v211` | مرشح Tanzil والفهارس والبصمات المحجورة للمراجعة |

إصدارات FSRS وقارئاتها وبياناتها القديمة محفوظة دون ترحيل دلالي. أرقام التجربة الجديدة لا تدمج بتاريخ FSRS ولا تدّعي الإتقان. التعاهد يستخدم المرشح الحسابي المتساوي المذكور صراحة في القسم 7 وأمثلة TA01–TA04؛ صياغة ترتيب التباعد الوصفية ليست مطابقة تمامًا للصيغة الحسابية، ولذلك لا يُقدَّم المحاكي بوصفه اعتمادًا تربويًا عامًا.

الحسابات الحقيقية والتحقق من البريد والمزامنة والاستعادة على جهاز آخر وحذف حساب الخادم غير مفعلة؛ تحتاج محول مزود معتمدًا. التخزين الجديد خاص بالبيانات الاصطناعية فقط، ولا يدعي تشفيرًا إنتاجيًا أو حفظًا سحابيًا. تصحيح تكرار الحفظ يعيد الإسقاط ويعلّق النطاقات المتأثرة، لكن محرر التصحيحات العامة وحل تداخل المواعيد تفاعليًا ليسا مكتملين. لا يُعدل موعد يدوي تلقائيًا عند التعارض.

## بناء المعاينة المستضافة والتحقق منها

```sh
node scripts/preview-v211.mjs --hosted
node scripts/package-v211-site.mjs
MULAZAMA_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node scripts/test-v211-hosted.mjs
```

البناء يقرأ الهوية والأصل الخاص الثابتين في `deployment/v211-private.json`، ثم يتحقق من الأصول قبل إنتاج `dist-v211-hosted`. إعادة البناء وحدها لا تنشر؛ النشر عبر Sites يجب أن يحافظ على وصول المالكة فقط وعلى هوية Site القائمة. لا تنشر شجرة المستودع أو `content` أو `docs`، ولا تربط قاعدة إنتاج.

أداة فحص الرابط تقرأ JSON يحوي الحقل `token` من **stdin فقط** حتى نهاية الإدخال. تُمرر صلاحية خدمة Site القائمة من ذاكرة جلسة الأداة مباشرة؛ لا تُكتب في وسيطات الأمر أو ملف أو سجل، ولا تُطبع. يرسل الفحص الرأس إلى الأصل المحدد فقط، ويرفض تحويله إلى أصل آخر. هذا اختبار خدمة مقيد، ولا يتجاوز شاشة تسجيل دخول المالكة في الاستخدام العادي. تبقى بيانات التصدير وoutbox محلية واصطناعية.

في GitHub CI يُستخدم Chromium المثبت بواسطة إصدار Playwright المثبت؛ لا تعيّن مسار Chromium المحلي هناك. لا توجد خطوة نشر في CI. للاختبارات على لقطة ملتزمة مع حفظ أدلتها التاريخية، يشمل الجرد الحالي اختبارات حاجز أصل الاستضافة الستة:


أعداد الاختبارات المطلوبة صريحة لهذه اللقطة ولا تُخفض عن الجرد التاريخي؛ دليل التحقق الشامل السابق عند `55f4d891` يخص 930 اختبارًا قبل إضافة الحاجز. بوابات القرآن والإطلاق تظل **محجوبة** حتى عند نجاح الاختبارات الهندسية. لم يُدمج PR #19 في main ولم يُنشر شيء على `mulazama.com`.

## بناء الاستضافة الخاصة والتحقق منها

```sh
node scripts/preview-v211.mjs --hosted
node scripts/package-v211-site.mjs
```

ملف `deployment/v211-private.json` يثبت Site القائم والأصل المسموح. حزمة Worker في `dist-v211-hosted` تتضمن فقط الأصول المطابقة لبصمات manifest؛ لا تنشر مجلد المستودع أو `content`. تبقى حماية الوصول من سياسة Sites الخاصة بالمالكة، وليست من حاجز الأصل في المتصفح. لا تستخدم هذا البناء على النطاق الرسمي.

لإعادة فحص الرابط استخدم `scripts/test-v211-hosted.mjs` مع Chromium المهيأ. يقرأ JSON يحوي مفتاح `token` من stdin فقط؛ مرّره من أداة الأسرار في الذاكرة، دون وسيطات أو ملفات أو echo أو سجل طرفية، ولا تكتبه في الأمر. يرسل الاعتماد إلى أصل Site المحدد فقط، ويرفض التحويلات، ولا يحفظ traces أو HAR أو جلسات اعتماد. يسجل الفحص النتائج المنقحة والصورة في `evidence/https-preview*`. اعتماد الخدمة لا يختبر تسجيل دخول المالكة البشري ولا يستبدل سياسة وصول Sites.
