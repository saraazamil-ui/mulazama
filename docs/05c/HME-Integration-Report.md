## إكمال فعلي لمسائل فقد البيانات والميزانية — نتيجة المصدر الأخير

بعد فحص الفجوات المستقلة عن اعتماد المصحف، نُفذ `src/application/composite-application.ts` دون تغيير بوابات الإنتاج أو main. يتولى المنسق مخزن EventStore ماديًا واحدًا للنطاقين، وتقرأ خدمات المنتج والتعلم scoped views من المخزن نفسه. هوية الملف واحدة؛ `LearningApplication.open` يقبل userId مثبتًا من ملف المنتج، وreplayComposite يرفض اختلاف الهوية أو غياب أحد النطاقين أو ظهور نطاق ثالث.

المزايا الجديدة القابلة للتحقق:

1. **نسخة موحدة فعلًا:** exportBackup يقرأ لقطة واحدة من root store، يتحقق من نطاقيها ثم يستعمل AES-256-GCM/PBKDF2 السابقين. جميع raw events محفوظة بتوقيتها وإصداراتها وهويتها؛ لا تصدير للإسقاطات بدل الخام.
2. **استعادة ذرية واحدة:** يفحص replayProduct وreplayLearning والهوية والمحتوى المرخص قبل root.replace الوحيد. لا سلسلة استبدال قاعدتين يمكن أن تفقد نصف البيانات. فشل المعاملة أو CAS يبقي النطاقين الحيين؛ لا ترميم شكلي بعد كتابة جزئية.
3. **منع النسخ الجزئي:** scoped EventStore يحمل `backupScope=aggregate-only`، وتمنع ApplicationService.exportBackup/replaceFromBackup عملية مستقلة على ذلك النطاق. replace/clear المحليان محجوبان أيضًا. App S18 عند حقن learning دون data controller يعرض تعليق إدارة البيانات، ولا يتيح تصدير نسخة منتج ناقصة أو حذف نصف التاريخ.
4. **تزامن محافظ:** تغير النطاق الآخر وحده يسمح بدمج append عند ثبوت عدم تغير خام النطاق الحالي؛ تغير النطاق نفسه ينتج REVISION_CONFLICT. الاستعادة تلتقط root revision قبل فك النسخة؛ أي كتابة أثناء التحقق تمنع overwrite بالـCAS.
5. **حذف كامل:** reset الموحد يحتاج confirmed=true، ويكتب تهيئتين فقط بعملية ذرية وهوية مشتركة جديدة، محتفظًا بإعدادات البدء والعرض، مع حذف وقائع التعلم والتصريحات والأخطاء والخطط. reset المباشر على خدمة نطاق واحد محجوب.
6. **نتيجة commit صادقة:** بعد الاستبدال المتحقق تُحدّث الإسقاطات عبر reloadDataProjection. هذه قراءة خام لا تمنح إذن كتابة؛ كل send يبقى تحت release access. المحاولة النشطة المستوردة تُوسم منقطعة دائمًا. هذا يمنع إعلان فشل استعادة لمجرد انتهاء دليل release بين commit وإعادة عرض الإسقاط.
7. **ميزانية المستخدم الحقيقية:** adapter.replanFromProduct يقرأ effectiveBudget بعد product.refresh، شاملًا override اليوم، ويشترط configured=true. S11 لا يبدأ بـ30 دقيقة مستقلة؛ يطلب وقتًا منفقًا وكلفة لكل وحدة صراحة، ويرفض الناقص. تحفظ كلفة التخطيط في المرشحين ووسمها `user-entered-estimate-05c-unvalidated`؛ لا ادعاء أنها زمن مقاس أو نموذج معاير. نقص الوقت يبقي الواجب deferred.
8. **زمن التدريب:** S07 يتيح إقرار الزمن والتعب صراحة ويعطل المتابعة عند قرار rest أو التعب. الغياب يظل TRAINING_TIME_NOT_MEASURED؛ `elapsedTimeProvided` لا يعني قياسًا آليًا. زمن جلسة foreground monotonic محفوظ مع lifecycle/pause/تعطل لم يُنفذ؛ يتطلب طبقة منصة واختبار متصفح، ولا نستعيض عنه بافتراض elapsed=0. ملفات المنهج وقيود الوقت تحتاج معايرة مستقلة.
