# MULAZAMA cloud development

- Use `https://github.com/saraazamil-ui/mulazama` and its current `main` as the source of truth. A prepared cloud checkout can be stale.
- A prepared snapshot may lack every project startup script. The environment Setup field must contain the complete self-contained `scripts/cloud-bootstrap09b.sh`, not a command pointing to a file in that stale snapshot. See `docs/09b/Environment-Fields.md` for the exact fields and acceptance check.
- For each new task, record the initial repository/branch/HEAD and environment version before repair, then run the published environment's `python3 /workspace/mulazama-cloud09b/bootstrap.py`. Use the new `MULAZAMA_WORKTREE` printed by that invocation. It fetches before installing, preserves the old checkout, creates a separate branch/worktree, and installs with the frozen lockfile. A missing launcher is an incomplete environment setup; report it explicitly. Do not reset or discard work. Do not start another bootstrap on every resumption of an existing task.
- From a current clean checkout, `python3 scripts/cloud-start08a.py --branch codex/<unique-task>` remains available for branch creation; it cannot bootstrap a snapshot where the script is absent and it does not install dependencies.
- Work on a separate branch. Open a pull request; never push directly to main, merge, enable auto-merge, or deploy without explicit owner authorization.
- Do not rewrite Git history, change Quran source bytes, reinterpret learner events, or change FSRS behavior as part of environment maintenance.
- Keep `productionReady=false` and G01–G10 blocked until the separate scientific and engineering approvals are complete. Passing tests is not content or launch approval.
- Use `python3 scripts/verify-08a.py` to verify a committed snapshot without overwriting historical delivery evidence. In this cloud image, explicitly select `/usr/bin/chromium` with `MULAZAMA_CHROMIUM_EXECUTABLE_PATH`; GitHub CI retains the pinned Playwright browser.
- Report failed, skipped, blocked and unrun checks separately. Never weaken assertions or hide failures to obtain a green result.
- This file is agent guidance, not enforced GitHub branch protection or proof of a platform startup hook. Reusable cloud environment publication and an independent new-task acceptance test remain separate steps; see `docs/09b/Environment-Fields.md` and `docs/08a/Cloud-Readiness.md`.
